# Docling 224 服务器 SSH 接入与真实验证（历史记录）

> 当前版本已切换为免 SSH 的校园网 HTTPS 入口，使用方法与维护见 [校园网 Docling 接入说明](docling-campus-https.md)。以下保留原 SSH 方案的验证记录。

## 默认连接

默认目标为 `ubuntu@101.76.222.224` 的 SSH 22 端口。Docling 仅监听远端 `127.0.0.1:5001`，PaperMind 首次解析时自动建立本地 `127.0.0.1:5001` 到远端同地址的转发。

设置中的 Docling 根地址保持 `http://127.0.0.1:5001`，OCR 和公式识别默认启用，解析超时默认 600 秒。无需配置原 A100 的 `yrhA100` 别名。用户显式配置的其他服务地址继续保留，切换默认服务器不会覆盖个人设置。

每台客户端需要可达服务器并具备自己的免交互 SSH 登录能力。首次使用前向管理员核实主机指纹，再建立主机信任；私钥不得放入仓库或安装包。验证命令：

```bash
ssh -o BatchMode=yes ubuntu@101.76.222.224 true
```

应用会复用本地 5001 端口上已有的监听。如果此前手动建立了指向其他服务器的隧道，应先确认并关闭自己的旧隧道，再重新测试，避免复用错误服务。本次真实验证开始前确认本地 5001 没有监听，由更新后的生产代码创建新隧道。

这是 SSH 连接方案，不是新增校园网 HTTPS 入口，也不会免除其他用户的 SSH 授权要求。自建远程 HTTPS 服务仍可通过设置填写根地址和可选 API Key。

## 验证方法

使用 Node 24.22.1 / npm 10.9.4 运行生产 `doclingTunnel`、`doclingClient`、`createSummaryParser`、`parseHtmlSummary`、Pinia 摘要生成与 SQLite 摘要仓库。连接测试通过同一自动 SSH 隧道访问 OpenAPI；PDF 转换实际上传到该服务器，摘要实际调用当前配置的 LLM。

从用户数据库只读取得真实 PDF、网页快照和当前模型配置，测试原文、解析材料、图片和摘要仅写入独立测试数据库。密钥只在进程内使用，不写入测试数据库、报告或仓库。网页测试使用已保存的真实 HTML + MHTML 快照，覆盖归档解析和新摘要生成，不代表重新在线采集网页。

PDF 摘要使用 Docling；网页摘要直接解析 HTML 与归档图片，不额外调用 Docling，这是当前生产链路的既定行为。

## 验证结果

真实输入：53 页 DeepSeek-V3 技术报告 `2412.19437v1.pdf`，以及 Lil'Log 的 “Harness Engineering for Self-Improvement” 已保存网页快照。模型为当前配置的 `deepseek-flash`。

两份报告均验证 SQLite 保存后内容一致、任务状态为 completed，重建解析器和 Pinia 后可重新加载；再次生成命中材料及报告缓存，新增网络请求为 0。摘要备份校验通过，SQLite foreign_key_check 为空。

测试结束后关闭本次自动创建的 SSH 隧道，确认本地 5001 端口已释放，远端服务仍 active 且健康检查正常。原用户数据库只读打开，未导入、清空或覆盖真实用户数据。完整 JSON、Markdown、图片和生产渲染器生成的 HTML 保存在仓库外的本次本机测试成果目录。
