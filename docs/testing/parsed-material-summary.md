# 解析材料摘要链路

## 本轮行为

- 网页摘要读取归档的 HTML 与同一快照内的 MHTML 图片，不再依赖网页转 PDF 或逐页图片输入。纯 HTML 历史记录也可生成摘要；没有保存的图片、Canvas 像素和无法安全转换的 SVG 会作为缺失材料明确记录。
- PDF 摘要通过 Docling 的 Heron、TableFormer accurate、RapidOCR、CodeFormulaV2 配置解析。摘要保留全部图、标题级别、表格结构、公式和未关联的图表说明；原有 Docling 解读接口的筛选保持兼容。
- `documentSummary.parse` 返回统一材料。正文、图表、公式和所有可用原图一次送到当前 OpenAI 兼容 LLM，新的中文提示词要求以原文为依据，保留限定条件并有选择解释图表。
- PDF 与网页摘要默认使用简体中文，覆盖标题、正文、图表说明和公式解释；专有名词、论文原名、原文引文、公式符号和素材编号可保留原文，续写仍要求简体中文。语言要求内置于摘要提示词，不依赖用户填写模型系统提示。提示词版本已更新，重新生成会使用新规则；历史报告保持原内容。
- 材料、图片和报告继续保存在现有 SQLite 摘要表。模型密钥不进入缓存。旧报告可阅读；新生成不复用旧页面视觉定位材料。
- 同源生成串行，不同来源独立；取消后迟到响应不更新报告。续写调整输出上限仍保留完整的历史前文。

## 范围与限制

本轮未增加语义素材选择、章节 map/reduce、流式输出或逐句证据对齐。输入安全上限为文本 2 MiB（含提示词与续写上下文）、图片 120 张、单图 12 MiB、图片总计 48 MiB；超出上限明确失败，不静默截断。模型自身上下文上限仍由其 API 决定。

HTML 原生结构和已缓存图片是摘要依据；HTML 中没有保存的动态渲染内容不能从 DOM 凭空恢复。页面原貌预览与原有归档机制继续独立工作。

托管服务隧道连接 `ubuntu@101.76.222.224`，将本地 5001 端口转发到该服务器的 Docling 服务。客户端 SSH 配置与最新真实联调范围见 [Docling 服务器接入说明](docling-server-224.md)。摘要生成继续使用当前 LLM 配置。

## 验证

使用独立 Node 24.22.1 和 npm 10.9.4，未更改系统 Node。测试运行时 `TMPDIR=/private/tmp`，使 macOS 临时目录与真实路径一致，避免既有文件恢复测试中 `/var` 和 `/private/var` 的路径别名差异。

自动测试覆盖 HTML 全文、标题、复杂表格、MathML、SVG、MHTML MIME 图片、缺图警告；Docling 请求参数与结构保留；完整材料的一次 LLM 请求；缓存、取消、三请求串行、续写和跨页面生命周期。另有使用真实 SQLite 的两条集成场景，只有 Docling/LLM 的外部 HTTP 响应使用受控替身，验证缓存恢复和备份中的原图归属。

完整安装包构建被既有运行时安全检查阻止：锁定的 Electron 44.9.3 实际携带 Node 24.22.0，而仓库要求至少 24.22.1。未绕过该门禁；独立前端/主进程/预加载源码打包用于验证编译，不代表安装包可发布。`sharp` 已移为运行时依赖，并为 `sharp` 和 `@img` 配置 ASAR 解包。

最终本地验证：`npm test` 通过 173 个 Vitest 文件 / 2153 项测试；脚本测试 23 通过、1 跳过（本机未安装 desktop-file-validate），0 失败。`npm run typecheck`、`vite build`（前端、Electron main、preload）及 `git diff --check` 均通过。独立审查已报告的问题全部修复并覆盖回归。
